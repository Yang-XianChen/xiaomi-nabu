# charge-control configuration guide

[English](配置文档.en.md) | [简体中文](配置文档.md)

## Behavior rules

| Battery level (%) | Action |
| --- | --- |
| `> 75` | Stop charging (standby) |
| `< 50` | Allow charging (switching) |
| `50 ~ 75` | Keep the current state |

Thresholds use strict comparison: at exactly 75% charging is not stopped
(76% is), and at exactly 50% charging is not resumed (49% is).

## Command-line arguments

| Argument | Default | Description |
| --- | --- | --- |
| `--stop <N>` | 75 | Stop-charging threshold |
| `--start <N>` | 50 | Allow-charging threshold |
| `--interval <N>` | 20 | Regular battery check interval (seconds, minimum 5) |
| `--watch-interval <N>` | 2 | Power-presence monitoring interval (seconds, minimum 1) |
| `--battery <PATH>` | auto-detect | Battery sysfs directory |
| `--charger-psy <PATH>` | ln8000-charger | Charger power_supply directory |
| `--i2c-dev <DEV>` | /dev/i2c-1 | I2C device |
| `--i2c-addr <ADDR>` | 0x51 | LN8000 chip address |
| `--once` | off | Run a single check and exit |
| `--status` | off | Read-only display of current state, then exit |
| `--dry-run` | off | Print actions only, do not write registers |
| `--no-restore-on-exit` | off | Keep the current state on exit |
| `--verbose` | off | More detailed logs |

## Changing service parameters

```bash
sudo systemctl edit charge-control
```

Override `ExecStart`:

```ini
[Service]
ExecStart=
ExecStart=/usr/local/sbin/charge-control --stop 80 --start 60 --interval 15
```

```bash
sudo systemctl daemon-reload
sudo systemctl restart charge-control
```

## Service management

```bash
systemctl status charge-control
journalctl -u charge-control -f
systemctl stop charge-control    # stop the service (default: restore allow-charging)
systemctl start charge-control
systemctl disable charge-control # disable auto-start
```

When the service receives `SIGTERM`/`SIGINT`, it restores "allow charging" by
default if a charger is connected; to keep charging stopped after stopping the
service, append `--no-restore-on-exit` to `ExecStart`.

## Uninstall

```bash
sudo systemctl disable --now charge-control
sudo rm /etc/systemd/system/charge-control.service
sudo rm /usr/local/sbin/charge-control
sudo systemctl daemon-reload
```

## Power-presence detection

The program decides whether power is available in this order:

1. `ln8000-charger/present == 1`;
2. Scan all `USB` / `Mains` power supplies for `online == 1`
   (e.g. Type-C `tcpm-source-psy`).

The LN8000 driver occasionally misses plug/unplug events (`present` stays 0);
in that case, as long as the Type-C `online` is 1, the program will still
resume charging when the battery level is below the threshold.

## Notes

- Must run as root; `/dev/i2c-*` is only accessible to root by default;
- Only adapted for the LN8000 charging chip (Xiaomi Pad 5); confirm register
  definitions before porting to other hardware;
- After plugging/unplugging power, the kernel driver immediately restores
  charging; this service re-takes control within about 2 seconds;
- `ln8000-charger/status` shows the driver's internal flag; the real mode is
  determined by `SYS_STS` and `qcom-battery/status`.
