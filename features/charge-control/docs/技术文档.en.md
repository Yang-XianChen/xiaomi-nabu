## 1. Project overview

This service implements battery-level-based automatic charging control:

- Stops charging when battery level is **above 75%**;
- Allows charging when battery level is **below 50%**;
- Keeps the current state between 50% and 75% to avoid toggling repeatedly at
  threshold edges.

The kernel driver on the target device does not expose the standard
`charge_control_end_threshold` / `charge_control_start_threshold` interfaces
to user space, so this project analyzes the driver source, finds the LN8000
charging chip's mode-control register and operates it directly, implementing
the charging switch as a user-space daemon.

| --- | --- |

## 3. Feasibility research

### 3.1 Standard charging-threshold interface check

First check the standard Linux power-management interfaces:

```bash
ls /sys/class/power_supply/ln8000-charger/
```

Only attributes such as `constant_charge_voltage`, `input_current_limit`,
`present` and `status` exist; there is **no**
`charge_control_end_threshold` / `charge_control_start_threshold`.

Further checks:

- The driver module's embedded strings contain
  `POWER_SUPPLY_PROP_CHARGE_CONTROL_END_THRESHOLD` etc., but the corresponding
  sysfs files are not exported;
- The device tree node does not enable the feature;
- The module has no tunable parameters.

Conclusion: the standard sysfs approach is not available.

### 3.2 Driver source analysis

The driver source matching the current kernel (`ln8000_charger.c`) was
obtained from the sm8150-mainline kernel repository, yielding the following
key information:

**Register addresses (partial)**

| Register | Address | Description |
| --- | --- | --- |
| `DEVICE_ID` | 0x00 | Chip ID, should be 0x42 |
| `SYS_STS` | 0x03 | System state (current operating mode) |
| `IIN_CTRL` | 0x1B | Input current limit |
| `SYS_CTRL` | 0x1E | System control (charging-mode switch) |
| `V_FLOAT_CTRL` | 0x28 | Constant-voltage charging voltage |
| `CHARGE_CTRL` | 0x29 | Charging control |

**SYS_STS mode bits (0x03)**

| Bit | Meaning |
| --- | --- |
| bit3 | BYPASS (bypass mode) |
| bit2 | SWITCHING (switching charging mode) |
| bit1 | STANDBY (standby / charging stopped) |
| bit0 | SHUTDOWN (shutdown) |

**SYS_CTRL charging-mode control bits (0x1E)**

| Bit | Meaning |
| --- | --- |
| bit3 | `STANDBY_EN`, set to 1 to enter standby |
| bit0 | `EN_1TO1`, set to 1 to enter 1:1 bypass |

The driver's switching logic (`ln8000_change_opmode`):

```c
// Stop charging (standby)
val = (1 << LN8000_BIT_STANDBY_EN);            // bit3 = 1, bit0 = 0
ln8000_update_reg(info, LN8000_REG_SYS_CTRL, msk, val);

// Resume charging (switching)
val = (0 << LN8000_BIT_STANDBY_EN) | (0 << LN8000_BIT_EN_1TO1);
ln8000_update_reg(info, LN8000_REG_SYS_CTRL, msk, val);
```

The mask `msk` only includes bit3 and bit0; **all other bits stay unchanged**.

### 3.3 Driver behavior and limitations

- The driver internally records "whether charging is allowed" in
  `info->chg_en`;
- It listens to USB Type-C devices through the power_supply notifier and
  automatically calls `psy_chg_set_charging_enable()` on plug/unplug:
  - Charger plugged in → resume charging;
  - Charger unplugged → enter standby;
- `ln8000-charger/status` directly returns `info->chg_en`, so even if the
  hardware has entered standby this attribute may still show `Charging`; the
  real mode must be determined from `SYS_STS`;
- This control function is **not exposed through any user-space interface**.

### 3.4 Conclusion

Use **direct user-space I2C read/write of the LN8000 `SYS_CTRL` register** to
control the charging mode, exactly matching the kernel driver's internal
operation and modifying only bits bit3/bit0.

## 4. Control strategy

### 4.1 Threshold rules

| Battery level (%) | Action |
| --- | --- |
| `> 75` | Stop charging (standby) |
| `< 50` | Allow charging (switching) |
| `50 ~ 75` | Keep the current state |

Thresholds use strict comparison:

```python
if cap > args.stop:      # stop
elif cap < args.start:   # allow
else:                    # keep
```

So exactly 75% keeps the current state (76% stops) and exactly 50% keeps the
current state (49% resumes).

### 4.2 State machine

```
                cap > 75
  [allow charging] ──────────────▶ [stop charging]
      ▲                          │
      │                          │
      └──────────────────────────┘
        cap < 50 and charger connected
```

The program uses two monitoring layers:

- Every 2 seconds (`--watch-interval`), read power availability (`present` or
  any USB/Mains `online`);
- Every 20 seconds (`--interval`), read battery level and run the regular
  check.

Before every action, the **actual** `SYS_CTRL` value is read, and the register
is written only when the actual state differs from the target; it does not
rely on the in-memory historical state. Therefore, even if the kernel driver
resumes charging when a charger is plugged in, the program re-asserts the
battery threshold and stops charging within about 2 seconds after detecting
the power-state change.

Rules:

- Battery > 75%: execute "stop charging" regardless of the current state;
- Battery < 50% and power available (`present=1` or any USB/Mains `online=1`):
  execute "allow charging";
- Battery < 50% but power unavailable: skip (the driver enters standby itself);
- Any other range: no write operations.

### 4.3 Initial state at startup

- Battery > 75%: stop immediately;
- Battery < 50%: allow immediately;
- 50%–75%: do not intervene; keep the hardware's current mode.

## 5. Software design

### 5.1 Overall architecture

```text
systemd (charge-control.service)
        │
        ▼
charge-control main loop (src/main.rs)
        │
        ├── read /sys/class/power_supply/qcom-battery/capacity
        ├── read /sys/class/power_supply/ln8000-charger/present
        ├── decision (threshold + hysteresis)
        └── Ln8000::set_charging() ── I2C read/write SYS_CTRL (0x1E)
```

The program is implemented in Rust and compiles to a single aarch64 executable
(about 330 KB). At runtime it does not depend on Python or any other runtime;
it uses only the `libc` crate for ioctl, signals and time formatting, and uses
about 200 KB of memory.

> Migrated from the Python version to Rust on 2026-08-09; the control logic is
> fully equivalent. This repository only maintains the Rust version; the early
> Python prototype is not shipped with the feature.

### 5.2 Module structure

**`Ln8000` struct**

| Method | Purpose |
| --- | --- |
| `check_device()` | Read 0x00, verify chip ID == 0x42 |
| `read_reg(reg)` | Read a single-byte register (I2C_RDWR + repeated start) |
| `write_reg(reg, val)` | Write a single-byte register |
| `set_charging(enable)` | Read-modify-write SYS_CTRL, switch standby / switching |
| `sys_ctrl()` / `sys_sts()` | Read the current control/status registers |

**`set_charging()` core logic**

```rust
const STANDBY_BIT: u8 = 1 << 3;   // bit3
const EN1TO1_BIT: u8  = 1 << 0;   // bit0
const CTRL_MASK: u8   = STANDBY_BIT | EN1TO1_BIT;

let new = if enabled {
    cur & !CTRL_MASK                    // allow charging: switching
} else {
    (cur & !CTRL_MASK) | STANDBY_BIT    // stop charging: standby
};
```

The register is written only when the target value differs from the current
value.

**Main loop**

```text
loop {
    power = read power availability (present/online, every --watch-interval seconds)
    if power changed → re-assert immediately with the current battery level
    if time since last check >= --interval → re-assert with the battery level
    sleep(1s)
}
```

### 5.3 I2C access implementation details

Hardware address: I2C bus 1 (`/dev/i2c-1`), chip address `0x51`.

**An I2C read transaction with a repeated-start condition is required.**

The initial approach of "write the register address alone (with STOP), then
issue a separate read (with START)" failed: every register read returned 0x42
(the chip ID), meaning the register pointer resets to 0x00 after STOP.

The final implementation uses the `I2C_RDWR` ioctl (0x0707), with two messages
in a single transaction:

```text
msg[0]: write register address
msg[1]: repeated start, then read 1 byte
```

```rust
#[repr(C)]
struct I2cMsg {
    addr: u16,
    flags: u16,
    len: u16,
    buf: *mut u8,
}

#[repr(C)]
struct I2cRdwr {
    msgs: *mut I2cMsg,
    nmsgs: u32,
}
```

The transaction is submitted with `libc::ioctl(fd, I2C_RDWR, &mut data)`.

**Safety protections**

- Verify the chip ID at startup to avoid writing to the wrong device;
- Read-modify-write touches only bit3/bit0, preserving all other configuration
  bits;
- Polling interval minimum is 5 seconds, preventing frequent I2C access;
- Re-read the current register value before every write.

### 5.4 systemd service

```ini
[Unit]
Description=Battery charge control (stop >75%, allow <50%)
After=multi-user.target

[Service]
Type=simple
ExecStart=/usr/local/sbin/charge-control --stop 75 --start 50 --interval 20
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Design points:

- `Restart=on-failure`: automatically restarted after an abnormal exit;
- On `SIGTERM`/`SIGINT` the service restores "allow charging" by default
  (when a charger is connected), so the device does not remain in
  stop-charging state after the service is stopped;
- `--no-restore-on-exit` can be used to keep the current state on exit;
- Auto-start on boot: `systemctl enable charge-control`.

| Step | Action | Battery | Battery state | SYS_STS | Result |
| --- | --- | --- | --- | --- | --- |
| 1 | Start service | 77% | Discharging | 0x02 standby | Charging stopped ✓ |
| 2 | Stop service | 77% | Charging | 0x04 switching | Charging resumed ✓ |
| 3 | Start service again | 77% | Discharging | 0x02 standby | Stopped again ✓ |
| 4 | `systemctl enable --now` | 77% | Discharging | 0x02 standby | Service active + enabled ✓ |
| 5 | Simulate driver resuming charging after plug-in, then re-take control | 78% | Discharging | 0x02 standby | Stopped again after fix ✓ |
| 6 | LN8000 misses present (present=0, tcpm online=1) | 42% | Charging | 0x04 switching | Charging resumed after combined online check ✓ |

> A previously found issue: the old version used the in-memory `state` to
> decide "already stopped" and did not write again; the driver resumes
> charging on plug-in, so the battery kept charging even above 75%.
> This was fixed by re-asserting against the actual hardware register state
> each time, taking control within about 2 seconds after plug/unplug.

## 8. Safety and risk control

1. **Minimal operation surface**: only bits bit3/bit0 of `SYS_CTRL` are
   modified; no other register bits are touched;
2. **Device verification**: chip ID 0x42 must be read before any write;
3. **Recoverability**: the default is to restore "allow charging" when the
   service stops or exits abnormally;
4. **Rate limiting**: regular battery checks default to every 20 seconds
   (minimum 5); power-state monitoring defaults to every 2 seconds;
5. **Plug/unplug race**: the driver immediately resumes charging when a
   charger is plugged in; the LN8000 driver may miss `present`, so this
   service also checks USB/Mains `online` and re-takes control by threshold
   within about 2 seconds of detecting a power-state change;
6. **State ambiguity**: `ln8000-charger/status` may show `Charging`, but it
   reflects the driver-internal `chg_en` flag, not the real hardware mode;
   use `SYS_STS` and `qcom-battery/status` as the source of truth;
7. **Hardware adaptation limits**: this solution targets the LN8000 chip and
   the current kernel driver; register definitions must be re-confirmed
   before porting to other devices;
8. **Permissions**: `/dev/i2c-*` is only accessible to root by default; the
   service runs as root.

## 9. Future improvements

- **Kernel-side improvements**: patch the ln8000 driver to export
  `CHARGING_ENABLED` or `CHARGE_CONTROL_END_THRESHOLD` as sysfs attributes,
  replacing direct user-space I2C writes;
- **Event-driven**: use udev / power_supply events or inotify to reduce
  response latency from polling intervals to milliseconds;
- **Desktop integration**: expose the current policy via D-Bus / upower and
  support GUI configuration;
- **Persistent configuration**: store thresholds in
  `/etc/charge-control.conf` instead of modifying the systemd unit;
- **Abnormal alarms**: alert via systemd logs or desktop notifications when
  I2C operations fail consecutively.
