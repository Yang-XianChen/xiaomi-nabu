## 1. 项目概述

本服务实现基于电池电量的充电自动控制：

- 电量 **大于 75%** 时停止充电；
- 电量 **低于 50%** 时允许充电；
- 电量处于 50%~75% 之间时保持当前状态，避免在阈值边缘反复切换。

目标设备的内核驱动没有向用户态暴露标准的
`charge_control_end_threshold` / `charge_control_start_threshold` 接口，
因此本项目通过分析驱动源码，找到并直接操作 LN8000 充电芯片的模式控制寄存器，
以用户态守护进程的方式实现充电开关。

## 3. 可行性调研

### 3.1 标准充电阈值接口检查

先检查 Linux 电源管理标准接口：

```bash
ls /sys/class/power_supply/ln8000-charger/
```

结果只有 `constant_charge_voltage`、`input_current_limit`、`present`、`status`
等属性，**没有** `charge_control_end_threshold` / `charge_control_start_threshold`。

进一步检查：

- 驱动模块内嵌字符串包含 `POWER_SUPPLY_PROP_CHARGE_CONTROL_END_THRESHOLD` 等，
  但对应 sysfs 文件并未导出；
- 设备树节点没有开启该功能的属性；
- 模块没有可调参数。

结论：标准 sysfs 方案不可用。

### 3.2 驱动源码分析

从 sm8150-mainline 内核仓库取得与当前内核一致的驱动源码
（`ln8000_charger.c`），得到以下关键信息：

**寄存器地址（部分）**

| 寄存器 | 地址 | 说明 |
| --- | --- | --- |
| `DEVICE_ID` | 0x00 | 芯片 ID，应为 0x42 |
| `SYS_STS` | 0x03 | 系统状态（当前工作模式） |
| `IIN_CTRL` | 0x1B | 输入限流 |
| `SYS_CTRL` | 0x1E | 系统控制（充电模式开关） |
| `V_FLOAT_CTRL` | 0x28 | 恒压充电电压 |
| `CHARGE_CTRL` | 0x29 | 充电控制 |

**SYS_STS 模式位（0x03）**

| Bit | 含义 |
| --- | --- |
| bit3 | BYPASS（旁路模式） |
| bit2 | SWITCHING（开关充电模式） |
| bit1 | STANDBY（待机/停止充电） |
| bit0 | SHUTDOWN（关断） |

**SYS_CTRL 充电模式控制位（0x1E）**

| Bit | 含义 |
| --- | --- |
| bit3 | `STANDBY_EN`，置 1 进入待机 |
| bit0 | `EN_1TO1`，置 1 进入 1:1 旁路 |

驱动中的切换逻辑（`ln8000_change_opmode`）：

```c
// 停止充电（standby）
val = (1 << LN8000_BIT_STANDBY_EN);            // bit3 = 1, bit0 = 0
ln8000_update_reg(info, LN8000_REG_SYS_CTRL, msk, val);

// 恢复充电（switching）
val = (0 << LN8000_BIT_STANDBY_EN) | (0 << LN8000_BIT_EN_1TO1);
ln8000_update_reg(info, LN8000_REG_SYS_CTRL, msk, val);
```

其中掩码 `msk` 只包含 bit3 与 bit0，**其余位保持不变**。

### 3.3 驱动行为与限制

- 驱动内部用 `info->chg_en` 记录“是否允许充电”；
- 通过 power_supply notifier 监听 USB Type-C 设备，插拔时自动执行
  `psy_chg_set_charging_enable()`：
  - 插入充电器 → 恢复 charging；
  - 拔出充电器 → 进入 standby；
- `ln8000-charger/status` 直接返回 `info->chg_en`，所以即使硬件已进入
  standby，该属性仍可能显示 `Charging`；真实模式要以 `SYS_STS` 为准；
- 该控制函数**没有暴露为任何用户态接口**。

### 3.4 结论

采用 **用户态直接 I2C 读写 LN8000 `SYS_CTRL` 寄存器** 的方式控制充电模式，
实现与内核驱动内部完全一致的操作，且只修改 bit3/bit0 两个位。

## 4. 控制策略

### 4.1 阈值规则

| 电量（%） | 动作 |
| --- | --- |
| `> 75` | 停止充电（standby） |
| `< 50` | 允许充电（switching） |
| `50 ~ 75` | 保持当前状态 |

阈值采用严格比较：

```python
if cap > args.stop:      # 停止
elif cap < args.start:   # 允许
else:                    # 保持
```

因此 75% 整点仍保持原状态，76% 才停止；50% 整点仍保持原状态，49% 才恢复。

### 4.2 状态机

```
                cap > 75
  [允许充电] ──────────────▶ [停止充电]
      ▲                          │
      │                          │
      └──────────────────────────┘
        cap < 50 且充电器已接入
```

程序采用两层监测：

- 每 2 秒（`--watch-interval`）读取一次电源可用性（`present` 或任意 USB/Mains 的 `online`）；
- 每 20 秒（`--interval`）读取一次电量并执行常规检查。

每次执行动作前都会读取 `SYS_CTRL` 的**实际值**，只在实际状态与目标不一致时
写入，不依赖程序内存中的历史状态。因此即使内核驱动在插入充电器时恢复了充电，
程序也会在监测到电源状态变化后约 2 秒内重新按阈值停止充电。

规则：

- 电量 > 75%：无论当前状态，执行“停止充电”；
- 电量 < 50% 且电源可用（`present=1` 或任意 USB/Mains `online=1`）：执行“允许充电”；
- 电量 < 50% 但电源不可用：跳过（驱动会自行进入 standby）；
- 其余区间：不产生任何写操作。

### 4.3 启动时的初始状态

- 电量 > 75%：立即停止；
- 电量 < 50%：立即允许；
- 50%~75%：不干预，保持硬件当前模式。

## 5. 软件设计

### 5.1 总体架构

```text
systemd (charge-control.service)
        │
        ▼
charge-control 主循环 (src/main.rs)
        │
        ├── 读取 /sys/class/power_supply/qcom-battery/capacity
        ├── 读取 /sys/class/power_supply/ln8000-charger/present
        ├── 决策（阈值 + 迟滞）
        └── Ln8000::set_charging() ── I2C 读写 SYS_CTRL (0x1E)
```

程序以 Rust 实现，编译为单个 aarch64 可执行文件（约 330KB），运行时不依赖
Python 或其它运行时，仅使用 `libc` crate 提供 ioctl、signal 与时间格式化，
服务运行时内存占用约 200KB。

> 2026-08-09 已由 Python 版迁移到 Rust 版，控制逻辑完全等价；
> 本仓库只维护 Rust 版；早期 Python 原型不随 feature 发布。

### 5.2 模块结构

**`Ln8000` 结构体**

| 方法 | 作用 |
| --- | --- |
| `check_device()` | 读 0x00，校验芯片 ID == 0x42 |
| `read_reg(reg)` | 读单字节寄存器（I2C_RDWR + 重复起始） |
| `write_reg(reg, val)` | 写单字节寄存器 |
| `set_charging(enable)` | 读改写 SYS_CTRL，切换 standby / switching |
| `sys_ctrl()` / `sys_sts()` | 读取当前控制/状态寄存器 |

**`set_charging()` 核心逻辑**

```rust
const STANDBY_BIT: u8 = 1 << 3;   // bit3
const EN1TO1_BIT: u8  = 1 << 0;   // bit0
const CTRL_MASK: u8   = STANDBY_BIT | EN1TO1_BIT;

let new = if enabled {
    cur & !CTRL_MASK                    // 允许充电：switching
} else {
    (cur & !CTRL_MASK) | STANDBY_BIT    // 停止充电：standby
};
```

仅当目标值与当前值不同时才写寄存器。

**主循环**

```text
loop {
    power = 读取电源可用性（present/online，每 --watch-interval 秒）
    if power 变化 → 立即按当前电量重新断言
    if 距上次检查 >= --interval → 按电量重新断言
    sleep(1s)
}
```

### 5.3 I2C 访问实现细节

硬件地址：I2C 总线 1（`/dev/i2c-1`），芯片地址 `0x51`。

**必须使用带重复起始条件的 I2C 读事务**

最初使用“先单独写寄存器地址（带 STOP），再单独发起读（带 START）”的方式，
发现读取任意寄存器都返回 0x42（芯片 ID），说明寄存器指针在 STOP 后复位到 0x00。

最终改用 `I2C_RDWR` ioctl（0x0707），单次事务包含两条消息：

```text
msg[0]: 写寄存器地址
msg[1]: 重复起始后读取 1 字节
```

```rust
#[repr(C)]
struct I2cMsg {
    addr: u16,
    flags: u16,
    len: u16,
    buf: *mut u8,
}

#[repr(C)]
struct I2cRdwr {
    msgs: *mut I2cMsg,
    nmsgs: u32,
}
```

通过 `libc::ioctl(fd, I2C_RDWR, &mut data)` 提交事务。

**安全保护**

- 启动时校验芯片 ID，避免对错误设备写入；
- 读改写只影响 bit3/bit0，保留其它配置位；
- 轮询间隔下限 5 秒，防止频繁 I2C 访问；
- 所有写操作前重新读取当前寄存器值。

### 5.4 systemd 服务

```ini
[Unit]
Description=Battery charge control (stop >75%, allow <50%)
After=multi-user.target

[Service]
Type=simple
ExecStart=/usr/local/sbin/charge-control --stop 75 --start 50 --interval 20
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

设计要点：

- `Restart=on-failure`：异常退出自动拉起；
- 服务收到 `SIGTERM`/`SIGINT` 时默认恢复“允许充电”（充电器接入时），
  避免停掉服务后设备保持停止充电状态；
- 可通过 `--no-restore-on-exit` 改为退出时保持当前状态；
- 开机自启：`systemctl enable charge-control`。

## 8. 安全与风险控制

1. **操作面最小化**：只改写 `SYS_CTRL` 的 bit3/bit0，不触碰其它寄存器位；
2. **设备校验**：写入前必须读到芯片 ID 0x42；
3. **可恢复性**：服务停止/异常退出时默认恢复允许充电；
4. **频率限制**：电量常规检查间隔默认 20 秒，最低 5 秒；电源状态监测间隔默认 2 秒；
5. **插拔竞争**：插入充电器时驱动会立即恢复充电；LN8000 驱动可能漏记
   `present`，本服务同时检查 USB/Mains 的 `online`，监测到电源状态变化后
   约 2 秒内重新按阈值接管；
6. **状态歧义说明**：`ln8000-charger/status` 可能显示 `Charging`，但它反映
   的是驱动内部 `chg_en` 标志，不代表硬件真实模式；应以 `SYS_STS` 和
   `qcom-battery/status` 为准；
7. **硬件适配限制**：本方案针对 LN8000 芯片与当前内核驱动实现，移植到其它
   设备前必须重新确认寄存器定义；
8. **权限要求**：`/dev/i2c-*` 默认仅 root 可访问，服务以 root 运行。

## 9. 后续改进方向

- **内核侧完善**：为 ln8000 驱动补丁，将 `CHARGING_ENABLED` 或
  `CHARGE_CONTROL_END_THRESHOLD` 属性导出为 sysfs，替代用户态 I2C 直写；
- **事件驱动**：改用 udev / power_supply 事件或 inotify 监听，将响应延迟从
  轮询间隔降到毫秒级；
- **桌面集成**：通过 DBus / upower 暴露当前策略，支持 GUI 配置；
- **配置持久化**：使用 `/etc/charge-control.conf` 保存阈值，避免修改
  systemd 单元；
- **异常告警**：I2C 连续失败时通过 systemd 日志或桌面通知告警。
