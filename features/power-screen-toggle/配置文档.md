# 电源按键与合盖行为改造 — 配置文档

> 文档日期：2026-08-08  
> 适用设备：Xiaomi Pad 5（Ubuntu 26.04 LTS / GNOME Shell 50.1 / Wayland / systemd 259）

## 1. 目标

- 短按电源键：仅切换屏幕开关，不再关机、不再弹出关机菜单。
- 合盖：仅关屏；开盖：仅开屏，不再挂起/休眠。
- 屏幕关闭必须是“真正关闭内容”，而非只关背光（避免打光后看到内容残影）。
- 开屏后触摸/鼠标映射立即恢复正常（无需手动重新开关鼠标）。
- 系统挂起/休眠唤醒后自动恢复背光（唤醒即亮屏）。

## 2. 最终行为

| 事件 | 行为 |
| --- | --- |
| 短按电源键 | 屏开 → 屏关并启动 15 秒挂起倒计时；屏关 → 屏开（恢复原亮度）并取消倒计时 |
| 键盘按键（屏幕关闭或 GNOME 已息屏时） | 开屏并刷新触摸/鼠标设备（同时取消挂起倒计时） |
| 合盖（SW_LID=1） | 关屏并启动 30 分钟挂起倒计时（若已有电源键倒计时则保持原倒计时，不重复关屏） |
| 开盖（SW_LID=0） | 开屏（恢复原亮度）并取消挂起倒计时 |
| 长按电源键 | 软件层忽略（硬件 PMIC 级强制断电不受软件控制，见第 7 节） |
| 挂起/休眠后唤醒 | 自动恢复背光（唤醒即亮屏），并重置挂起倒计时状态 |

## 3. 环境信息

- 系统：Ubuntu 26.04 LTS，systemd 259，GNOME Shell 50.1（Wayland）
- 设备：Xiaomi Pad 5（DMI: Xiaomi / Pad 5，aarch64）
- 电源键：`pm8941_pwrkey` → `/dev/input/event0`（KEY_POWER=116）
- 合盖开关：`gpio-keys` → `/dev/input/event2`（SW_LID）
- 背光：`/sys/class/backlight/ktz8866-backlight`（最大 2047）
- 显示输出：DRM `card0-DSI-1`（DPMS 状态见 `/sys/class/drm/card0-DSI-1/dpms`）
- 指针/触摸设备：
  - `NVTCapacitiveTouchScreen`（触摸屏）
  - `NVTCapacitivePen`（触控笔）
  - `Xiaomi Pad Mouse`（USB 鼠标）
  - `CapacMouse-5 5.2 Mouse`（蓝牙鼠标）

> 以上是本机当前设备示例，不是白名单。任意符合 udev 属性的鼠标/触摸板
> （`ID_INPUT_MOUSE` / `ID_INPUT_TOUCHPAD` / `ID_INPUT_POINTINGSTICK`，
> 含 USB、蓝牙、2.4G 接收器设备）都会在连接后自动纳入监听（最多 3 秒），
> 移动或点击即可唤醒屏幕；触摸屏/触控笔不参与唤醒，仅用于开屏后的映射刷新。
- 守护进程状态文件：`/var/lib/screen-toggle/last-brightness`

## 5. 配置详解

### 5.1 systemd-logind：忽略电源键与合盖

文件 `/etc/systemd/logind.conf.d/10-screen-toggle.conf`：

```ini
[Login]
HandlePowerKey=ignore
HandlePowerKeyLongPress=ignore
HandleLidSwitch=ignore
HandleLidSwitchExternalPower=ignore
HandleLidSwitchDocked=ignore
LidSwitchIgnoreInhibited=yes
```

- 使 logind 不再对电源键执行默认的 `poweroff`，不再对合盖执行 `suspend`。
- `LidSwitchIgnoreInhibited=yes`：即使其他组件持有抑制器，也不触发挂起。

### 5.2 GNOME 电源设置

以用户 `yangxc` 身份执行（dconf 持久化，重启后仍生效）：

```bash
gsettings set org.gnome.settings-daemon.plugins.power power-button-action nothing
gsettings set org.gnome.settings-daemon.plugins.power lid-close-ac-action nothing
gsettings set org.gnome.settings-daemon.plugins.power lid-close-battery-action nothing
```

- `power-button-action` 原为 `interactive`（弹关机菜单），现为 `nothing`。
- 合盖动作原为 `suspend`，现为 `nothing`。

### 5.3 屏幕开关守护服务

服务单元 `/etc/systemd/system/screen-toggle.service`：

```ini
[Unit]
Description=Toggle display on power button and lid switch
After=local-fs.target

[Service]
Type=simple
ExecStart=/usr/local/sbin/screen-toggle-daemon
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
```

守护程序 `/usr/local/sbin/screen-toggle-daemon`（Rust 编译）功能：

- 自动探测电源键（KEY_POWER）与合盖开关（SW_LID）的输入设备节点，不依赖固定 event 编号。
- 关屏流程：
  1. 以会话用户身份调用 `gdbus`，设置 `org.gnome.Mutter.DisplayConfig.PowerSaveMode = 1`（合成器将 DRM 连接器置为 DPMS Off / disabled，面板彻底停止输出内容，消除残影）；
  2. 保存当前亮度到 `/var/lib/screen-toggle/last-brightness`；
  3. 背光写入 `0`。
- 开屏流程：
  1. `PowerSaveMode = 0`（恢复显示输出）；
2. 恢复显示输出后先保持背光为 `0` 约 0.7 秒，待 DSI 面板/触摸控制器重新初始化完成后再恢复亮度；
3. 开屏后检查内核日志中是否有 `NVT-ts-spi` 固件加载失败或面板初始化失败记录；若检测到失败，背光仍为 `0` 时自动执行最多 2 次 blank→unblank 恢复循环（连同首次开屏共 3 次尝试，相当于官方文档“再按两次电源键”的软件恢复），任一次成功即恢复亮度。**系统挂起唤醒后的第一次开屏会直接以一次完整 blank→unblank 循环替代常规 unblank**（即使内核没有报错），因为本机 NVT 面板在唤醒后即使日志显示 `Update firmware success` 仍可能黑屏，必须完整开关一次才能可靠点亮；用户此前遇到的“开盖黑屏、需再合盖开盖”即由此导致。恢复循环不再先做一次普通 unblank 再补一次循环，因此比旧实现少等待约 1.4 秒；
  3.0 内核日志检查窗口从发起 unblank **之前**开始计时，覆盖 `set_power_save(false)` 调用
      期间发生的固件加载失败（此前窗口起点偏晚，会漏掉这类失败导致开屏后黑屏）；
  3.1 恢复亮度时优先使用守护进程**持续跟踪的用户亮度**：屏幕点亮期间每 0.5 秒轮询 sysfs 亮度，并按
      GNOME `idle-brightness`（默认 30%）计算压暗值、自动忽略，因此 GNOME 自动压暗后的低亮度
      不会被当成用户设置保存；用户调整亮度后状态文件会自动更新。仅当跟踪值无效时才回退到
      Mutter Backlight 属性或旧状态文件。恢复亮度优先调用 Mutter 的 `SetBacklight` D-Bus 接口
      （使 GNOME 亮度设置与真实亮度保持同步），Mutter 拒绝的值（如关屏时的 0）或调用失败时才
      直接写 sysfs；写入后校验一次，若未生效自动重试；
  4. 屏幕点亮后立即在后台对触摸屏/触控笔执行 `udevadm trigger` remove+add，让合成器重新打开设备并重算触摸映射（解决开屏后方向错乱），最后执行 `udevadm settle`；刷新不再占用开屏时间，代价是点亮瞬间的第一次点击可能落在设备重开过程中；
  5. 先恢复之前保存的亮度，输入设备刷新在后台同时进行；
  6. 鼠标/触摸板等相对指针设备紧随其后在同一后台任务中刷新，不占用开屏时间；
  7. 开屏后再次检查 DPMS；若合成器（如 GNOME 空闲熄屏）立即重新熄灭，则自动再点亮一次。
- 挂起倒计时：
  * 电源键关屏：15 秒后若系统仍未进入挂起，自动执行 `systemctl suspend`；
  * 合盖关屏：30 分钟后若系统仍未进入挂起，自动执行 `systemctl suspend`；
  * 若已有倒计时时合盖（例如先按电源键再合盖），合盖不会重复关屏、也不会把 15 秒
    重置成 30 分钟，保持原有倒计时；
  * 充电状态下挂起控制禁用：电源键/合盖只关屏，不启动挂起倒计时；合盖唤醒也不会
    重新挂起（已开始的倒计时在检测到充电后也会被取消）；
  * 倒计时期间任何开屏信号（再按电源键、开盖、键盘按键、外部唤醒）都会亮屏并取消倒计时；
  * 系统挂起并唤醒后，守护进程重置倒计时状态并恢复背光（唤醒即亮屏）。
- 自动探测并监听键盘设备（`ID_INPUT_KEYBOARD=1`，本机为 `event6`、`event9`）和鼠标/触摸板设备
  （`ID_INPUT_MOUSE` / `ID_INPUT_TOUCHPAD` / `ID_INPUT_POINTINGSTICK`，本机为 `event7`、`event8`、`event10`）：
  当屏幕处于关闭状态或已被 GNOME 息屏时，任意按键、鼠标移动/点击或触摸板操作都会触发开屏。
  输入设备每 3 秒与系统比对一次，后连接的蓝牙键盘/鼠标会自动纳入监听；合盖状态下键盘/鼠标
  不会唤醒屏幕（电源键仍可）。

- 后台每 0.5 秒轮询 DPMS：若屏幕是被 GNOME 空闲息屏后由键盘/触摸唤醒的，守护进程会检测到这次“外部唤醒”，随后自动在后台刷新触摸屏、触控笔和鼠标/触摸板，解决唤醒后映射未刷新的问题。
- 所有外部命令调用（gdbus / loginctl / udevadm / journalctl）都有真正的超时保护：D-Bus 调用最长等待 5 秒，超时后杀掉整个进程组并按失败处理，守护进程继续运行。此前版本无超时，Mutter 偶发不响应时守护进程会永久阻塞（2026-08-09 开机后按电源键屏幕无法恢复、只能强制重启即由此导致）。
- 开屏时的 `PowerSaveMode = 0` 调用会重试最多 3 次，并以真实 DPMS 状态校验是否真的点亮；若合成器仍未点亮，守护进程**不会**把屏幕标记为已开，下一次按键/合盖开合会重新走完整开屏流程。这避免了“gdbus 回复丢失但屏幕实际黑着”被误判为开屏成功。
- 用户亮度跟踪：屏幕点亮时守护进程持续记录 sysfs 亮度，并利用 GNOME `idle-brightness` 设置识别
  `idle-dim` 的压暗值（默认 30% ≈ 628/2047），压暗值不会覆盖状态文件；因此恢复的是用户真正设置的
  亮度，而不是“每次固定的旧值”或“GNOME 自动压暗后的低亮度”。
- GNOME 亮度设置同步：开屏恢复亮度通过 Mutter `SetBacklight` 完成，Mutter 的 Backlight 属性
  会更新为真实值，GNOME 设置/快速设置里不再固定显示最低亮度；仅关屏写 0 和 Mutter 调用失败时
  才回退到直接写 sysfs。
- 系统唤醒后的第一次开屏（无论由 SIGUSR1、开盖还是电源键触发）直接以一次完整 blank→unblank 循环替代常规 unblank，背光保持为 `0` 不会闪屏；等价于自动完成官方“再按一次电源键”的黑屏恢复，不再依赖内核报错来触发。由于省掉了“先 unblank、等待、再 blank”的多余步骤，只增加一次 blank 和约 300ms 等待，对开屏速度影响很小。
- 收到 `SIGUSR1`（唤醒钩子触发）时：恢复背光并同步开关状态（唤醒即亮屏）。
- `SIGTERM`/`SIGINT`/`SIGUSR1` 处理器在脚本加载时即注册，避免唤醒信号在启动早期误杀进程。
- 按键方向判断以**实际显示状态**为准：后台每 0.5 秒轮询一次 DPMS 状态（`display_blanked`），并按“DPMS 关闭或背光为 0 视为暗屏”决定电源键是开屏还是关屏。这样即使 GNOME 先自动熄屏，按下电源键也会正确开屏，而不是错误地再关一次。
- 电源键带 1 秒防抖：开屏后短暂时间内再次按键会被忽略，避免快速连按导致“开→关”来回切换。
- 开屏过程较慢（例如面板恢复循环）时，期间排队等待的电源键事件会按事件时间戳判断为“开屏前
  按下”而忽略，避免开屏完成后又被立刻关屏（此前表现为“需要按多次电源键才能唤醒”）。


### 5.4 唤醒恢复钩子

服务单元 `/etc/systemd/system/screen-toggle-resume.service`：

```ini
[Unit]
Description=Resync display backlight after system resume
After=suspend.target hibernate.target hybrid-sleep.target suspend-then-hibernate.target

[Service]
Type=oneshot
ExecStart=/usr/bin/systemctl kill --kill-whom=main -s SIGUSR1 screen-toggle.service

[Install]
WantedBy=suspend.target hibernate.target hybrid-sleep.target suspend-then-hibernate.target
```

- 钩子只向守护进程主进程发送 `SIGUSR1`（`--kill-whom=main`），不会把信号发给服务 cgroup 里正在执行的
  `loginctl` / `runuser` / `gdbus` 子进程。此前用默认方式会把子进程一起杀掉，若恰好赶上开盖开屏，
  会打断 D-Bus 调用导致屏幕黑屏却无法自动重试。
- `suspend.target` 等目标在挂起/休眠结束后才激活，因此该钩子必然在“唤醒后”执行。
- 唤醒时先通过 `EVIOCGSW` 读取合盖开关的当前真实状态：若唤醒时合盖处于闭合（例如
  电源键挂起后再合盖），保持屏幕关闭并立即重新挂起（同一 60 秒窗口内最多自动重挂
  3 次，防止合盖唤醒死循环；超过后保持黑屏并转合盖 30 分钟倒计时）。若合成器在唤醒后
  尝试重新点亮显示器（外部 unblank），合盖状态下也会被忽略并重新关闭。
- 唤醒后无论屏幕是否已被合成器点亮，都会在后台刷新触摸屏/触控笔和鼠标/触摸板，
  避免开盖唤醒后触控映射失效。
- 磁吸触点键盘在挂起期间由硬件切断供电，唤醒后软件无法恢复（`usbhid` unbind/bind
  或设备级 `authorized` 开关都不能重新供电），需要物理重新吸附。守护进程不再自动
  重连键盘，避免与手动重连互相干扰。

## 6. 工作原理

```text
电源键按下 ──> pm8941_pwrkey 产生 KEY_POWER 事件
合盖/开盖 ──> gpio-keys 产生 SW_LID 事件
        │
        ▼
screen-toggle-daemon（root，systemd 服务）
        │
        ├── 关屏：mutter PowerSaveMode=1 → 背光=0
        ├── 开屏：PowerSaveMode=0 → 恢复亮度 → 输入设备 remove/add 刷新
        │         （后台轮询 DPMS，识别 GNOME 自动熄屏；按键方向按实际状态判断）
        └── SIGUSR1（唤醒）：恢复背光 + 同步状态

挂起/休眠唤醒 ──> screen-toggle-resume.service ──> SIGUSR1
```

- 屏幕关闭期间内核仍保持电源键/合盖为唤醒源（`power/wakeup=enabled`），不影响系统唤醒；守护进程同时监听键盘事件，键盘按下即视为开屏请求。
- 合成器侧使用与 GNOME 空闲熄屏完全相同的 `PowerSaveMode` 通道，状态一致、无冲突。
- 守护进程以 0.5 秒间隔轮询 DPMS，区分“本进程开屏”和“外部唤醒”：外部唤醒后自动在后台重加触摸/触控笔设备并刷新鼠标/触摸板。

### 6.1 持续花屏的自动恢复

本机定制内核的显示链路（Novatek NT36523 DSI 面板 + NVT-ts-spi 触摸控制器）
在 DPMS 关闭/恢复后偶尔初始化不完整，表现为：

- 触摸控制器固件重载**最终**失败（内核日志 `FW info is broken!`、
  `nvt_get_fw_info failed`、`download firmware failed`；`nvt_check_fw_reset_state
  error` 只是重试过程，最终 `Update firmware success` 仍算成功，不触发恢复）；
- 面板停留在花屏/乱码状态，直到再完整开关一次屏幕才恢复（与
  linux-on-nabu 官方已知问题一致）。

守护进程处理方式：

1. 每次开屏后保持背光为 `0`，先等待显示链路稳定；
2. 系统挂起唤醒后的第一次开屏直接以一次 `blank → unblank` 恢复循环替代
   常规 unblank（背光仍为 `0`），即使内核未报错也执行——本机在唤醒后经常
   出现“固件日志显示成功但面板实际黑屏”，只有完整开关一次才能点亮；不再
   先做一次普通 unblank 再补循环，减少约 1.4 秒开屏延迟；
3. 同时检查该次开屏时间窗口内的内核日志（仅以“最终失败”为准，忽略固件重试）；
4. 若检测到初始化失败记录，继续执行最多 2 次 `blank → unblank` 恢复循环，
   任一次成功即恢复亮度；全部失败才恢复亮度并记录日志，等待人工处理。

该恢复机制把“按两次/三次电源键”的手动操作自动化；恢复循环次数有上限
（唤醒后首次开屏固定 1 次 + 报错时最多 2 次），避免无限反复开关屏。

## 7. 已知问题与注意事项

1. **GDM 登录界面**：没有用户会话，无法调用合成器 D-Bus 接口，也无法刷新输入设备；此时退化为仅关闭背光（可能仍有残影）。进入桌面会话后行为完整。
2. **硬件长按电源键**：PMIC 级强制断电/复位属于硬件行为，无法通过软件关闭；短按功能不受影响。
3. **触摸映射问题**：mutter 在显示输出禁用/恢复后可能保留旧的触摸映射（竖屏坐标映射到横屏显示）。已通过在开屏时自动重加输入设备缓解；若仍异常，可尝试重启 gnome-shell。
4. **自动挂起**：未禁用系统自动挂起；唤醒后由钩子恢复背光，屏幕自动点亮。
5. **GNOME 自动熄屏交互**：GNOME 空闲自动熄屏同样使用 `PowerSaveMode=1`。守护进程已通过后台轮询识别该状态，因此“GNOME 已熄屏后按电源键”会正确开屏；由键盘/触摸等外部输入唤醒时，守护进程会检测到外部唤醒并自动刷新触摸/鼠标设备。开屏后若合成器立即重新熄灭，守护进程会自动再点亮一次。GNOME `idle-dim` 在自动熄屏前会把 sysfs 亮度临时压暗，守护进程恢复亮度时优先读取 Mutter 的 `Backlight` 用户亮度属性，不会停留在压暗值。
6. **稳定性提示**：本机定制内核的显示/触摸驱动（`NVT-ts-spi`、msm DRM）存在不稳定现象。每次开关屏都会触发 NVT 挂起/恢复与固件重载（日志可能出现 `nvt_check_fw_reset_state error` 重试）。2026-08-07 曾发生一次无内核日志的硬挂起/复位（疑似看门狗）。建议按正常频率使用，避免短时间内快速连续开关屏；若再次发生，请保存串口/控制台输出以便定位。
7. **自动恢复的检测边界**：当前以内核日志中的 NVT 固件加载失败/面板初始化失败作为恢复触发条件。若某次花屏没有任何内核报错记录（例如纯 GPU/合成器状态异常），守护进程无法“看见”它，仍需要手动开关一次屏幕。这类情况请保留 `journalctl -b --no-pager` 日志以便进一步定位。
8. **亮度状态文件曾被最小亮度覆盖**：修复前版本会把开屏时读到的 20（背光写 0 后 Mutter 返回的最小值）写回状态文件。若当前开屏仍为最暗，请先把亮度拖到你常用的亮度一次；之后关屏/息屏再开屏即可正确恢复。

### 11.1 开屏提速（2026-08-08）

分步计时发现旧版开屏约 3.6 秒，主要耗时是开屏前同步执行触摸设备刷新（约 2 秒）和
每次子进程的 `timeout` 包装固定开销（每条约 110 ms）。现已改为：

- 触摸屏/触控笔、鼠标/触摸板的 udev 刷新全部移到屏幕点亮后的后台执行；
- 去掉 `timeout` 包装（裸 `udevadm` 只需约 12 ms，包装后约 110 ms）。

实测从电源键按下到屏幕点亮由约 3.6 秒降至约 1.0 秒；剩余约 0.7 秒是保留的
DSI 面板/触摸控制器稳定等待，不建议继续缩短。
