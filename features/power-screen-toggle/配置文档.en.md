# Power Button & Lid Switch Behavior Rework — Configuration Guide

[English](配置文档.en.md) | [简体中文](配置文档.md)

> Applicable devices: Linux tablets/laptops with a power key, lid switch and
> backlight device (development target: Xiaomi Pad 5 / Ubuntu / GNOME Wayland /
> systemd). Device names and input event numbers in this document are examples;
> the daemon auto-detects everything and does not depend on fixed numbers.

## 1. Goals

- Short power-key press: only toggles the screen, does not shut down or show a
  power-off menu.
- Lid close: only turns the screen off; lid open: only turns it on, no
  suspend/hibernate.
- Screen off must mean the content is really disabled, not just the backlight
  (to avoid ghost images showing through).
- Touch/mouse mapping is restored immediately after the screen turns on.
- Backlight is restored automatically after system suspend/hibernate wake
  (screen is on right after wake).

## 2. Final behavior

| Event | Behavior |
| --- | --- |
| Short power-key press | Screen on → screen off and start a 15 s suspend countdown; screen off → screen on (restore original brightness) and cancel the countdown |
| Keyboard key / mouse move, click / touchpad gesture (while screen is off or blanked) | Turn screen on and refresh touch/pointer devices (also cancel the suspend countdown) |
| Lid close | Turn screen off and start a 30 min suspend countdown (if a power-key countdown already exists, keep it; do not turn the screen off again) |
| Lid open | Turn screen on (restore original brightness) and cancel the suspend countdown |
| Long power-key press | Ignored at the software level (hardware PMIC-level force power-off is not software-controllable, see Section 7) |
| Wake after suspend/hibernate | Backlight restored automatically (screen on after wake) and suspend countdown state reset |

## 3. Environment requirements

- Linux + systemd; GNOME Wayland recommended (compositor D-Bus channel:
  `org.gnome.Mutter.DisplayConfig`).
- Power-key input device (`KEY_POWER`), lid-switch input device (`SW_LID`).
- Backlight sysfs device (e.g. `ktz8866-backlight`).
- Optional: Novatek touch/display controller (enables automatic recovery cycles).

## 4. Change overview

| File | Purpose | Status |
| --- | --- | --- |
| `/etc/systemd/logind.conf.d/10-screen-toggle.conf` | logind ignores power-key and lid events | Written by the install script |
| `/usr/local/sbin/screen-toggle-daemon` | Resident daemon (Rust): listens for key/lid events and drives screen on/off | Written by the install script |
| `/etc/systemd/system/screen-toggle.service` | Daemon service | Enabled by the install script |
| `/etc/systemd/system/screen-toggle-resume.service` | Backlight restore hook after suspend/hibernate wake | Enabled by the install script |
| GNOME power settings | Power-key and lid actions set to "nothing" | Best-effort by the install script; can also be set manually |

## 5. Configuration details

### 5.1 systemd-logind: ignore power key and lid switch

`/etc/systemd/logind.conf.d/10-screen-toggle.conf`:

```ini
[Login]
HandlePowerKey=ignore
HandlePowerKeyLongPress=ignore
HandleLidSwitch=ignore
HandleLidSwitchExternalPower=ignore
HandleLidSwitchDocked=ignore
LidSwitchIgnoreInhibited=yes
```

### 5.2 GNOME power settings

Run as the graphical-session user:

```bash
gsettings set org.gnome.settings-daemon.plugins.power power-button-action nothing
gsettings set org.gnome.settings-daemon.plugins.power lid-close-ac-action nothing
gsettings set org.gnome.settings-daemon.plugins.power lid-close-battery-action nothing
```

### 5.3 Screen toggle daemon service

The daemon `/usr/local/sbin/screen-toggle-daemon` (compiled from Rust):

- Auto-detects the input device nodes for the power key (`KEY_POWER`), lid
  switch (`SW_LID`), keyboards (`ID_INPUT_KEYBOARD`) and mouse/touchpad
  (`ID_INPUT_MOUSE` / `ID_INPUT_TOUCHPAD` / `ID_INPUT_POINTINGSTICK`); it does
  not depend on fixed event numbers. It recompares with the system every 3
  seconds, so later-connected Bluetooth keyboards/mice are added automatically
  and disconnected devices are removed.
- Screen-off flow:
  1. As the session user, call `gdbus` and set
     `org.gnome.Mutter.DisplayConfig.PowerSaveMode = 1` (the compositor puts
     the DRM connector into DPMS Off / disabled, so the panel fully stops
     outputting content and ghost images are eliminated);
  2. Save the current user brightness;
  3. Write backlight `0`.
- Screen-on flow:
  1. Set `PowerSaveMode = 0` (restore display output), retry up to 3 times and
     verify against the real DPMS state; if the compositor still has not
     turned the screen on, **do not mark the screen as on** — the next key/lid
     event runs the full screen-on flow again;
  2. After display output is restored, keep the backlight at `0` for about
     0.7 s, then restore brightness after the DSI panel/touch controller has
     finished initializing;
  3. Brightness restore prefers Mutter `SetBacklight` (keeps GNOME brightness
     settings in sync); values Mutter rejects (e.g. 0) or call failures fall
     back to writing sysfs directly; the write is verified and retried
     automatically if it did not take effect;
  4. After the screen is on, refresh touchscreen/pen and mouse/touchpad
     devices in the background via udev remove/add so the compositor
     recomputes touch mapping, without delaying the screen-on;
  5. Check DPMS again after screen-on; if the compositor immediately blanks
     again, turn it on once more automatically.
- Suspend countdowns:
  - Power-key screen-off: if the system has not suspended after 15 s, run
    `systemctl suspend` automatically;
  - Lid-close screen-off: if the system has not suspended after 30 min, run
    `systemctl suspend` automatically;
  - If the lid is closed while a countdown already exists, do not turn the
    screen off again and do not reset the countdown;
  - While charging, suspend control is disabled: the power key/lid only turn
    the screen off and do not start a suspend countdown;
  - Any screen-on signal during a countdown turns the screen on and cancels
    the countdown.
- Keyboard/mouse/touchpad wake: while the screen is off or GNOME has blanked
  it, any key, mouse movement (≥ 2 units) or click, or touchpad gesture
  triggers screen-on; no wake while the lid is closed. Pointer wake is ignored
  for 2 s after the daemon turns the screen off (power key and keyboard are
  not affected), to avoid the screen immediately turning back on from hand
  movement while pressing the power key.
- External-wake brightness restore: when GNOME idle-blank is dismissed by
  keyboard/mouse, if the backlight is still at the `idle-dim` value or 0, the
  daemon restores the user brightness automatically (brightness only, without
  repeating the full screen-on flow), to avoid the screen appearing "not
  awake" and a second power-key press turning it off instead.
- Power-key debounce: a second press within 1 s after screen-on is ignored to
  avoid on→off toggling; after screen-off the debounce resets immediately, so
  pressing power again wakes the screen right away.
- When the screen-on process is slow (e.g. panel recovery cycles), queued
  power-key events are identified by event timestamp as "pressed before
  screen-on" and ignored, so the screen is not turned off immediately after
  it turns on.
- User-brightness tracking: while the screen is on, sysfs brightness is
  continuously recorded, and the `idle-dim` value is recognized from the
  GNOME `idle-brightness` setting (default 30%); the dimmed value never
  overwrites the user brightness; the state file updates automatically when
  the user adjusts brightness.
- The first screen-on after system wake replaces the normal unblank with a
  full blank→unblank cycle (backlight kept at 0): on this class of panel, even
  if the firmware logs success after wake the screen may stay black, and a
  full off/on cycle is needed to reliably light it up.
- All external command calls (gdbus / loginctl / udevadm / journalctl) have
  timeouts, so a wedged D-Bus call can never block the daemon forever.
- On `SIGUSR1` (triggered by the wake hook): restore the backlight and sync
  the on/off state.

### 5.4 Wake restore hook

`/etc/systemd/system/screen-toggle-resume.service`:

```ini
[Unit]
Description=Resync display backlight after system resume
After=suspend.target hibernate.target hybrid-sleep.target suspend-then-hibernate.target

[Service]
Type=oneshot
ExecStart=/usr/bin/systemctl kill --kill-whom=main -s SIGUSR1 screen-toggle.service

[Install]
WantedBy=suspend.target hibernate.target hybrid-sleep.target suspend-then-hibernate.target
```

- The hook only sends `SIGUSR1` to the daemon's main process
  (`--kill-whom=main`); it does not accidentally kill running loginctl /
  runuser / gdbus child processes.
- On wake, the real lid-switch state is read first: if the lid is closed, keep
  the screen off and suspend again immediately (max 3 times in the same 60 s
  window, to prevent a lid-wake loop).
- After wake, regardless of whether the compositor has already turned the
  screen on, touch/pointer devices are refreshed in the background.

## 6. How it works

```text
Power key pressed ──> power-key input device emits KEY_POWER event
Lid close/open ──> lid-switch input device emits SW_LID event
Keyboard/mouse ──> corresponding input device emits key/movement events
        │
        ▼
screen-toggle-daemon (root, systemd service)
        │
        ├── Screen off: mutter PowerSaveMode=1 → backlight=0
        ├── Screen on: PowerSaveMode=0 → restore brightness → refresh input devices in background
        └── SIGUSR1 (wake): restore backlight + sync state

Suspend/hibernate wake ──> screen-toggle-resume.service ──> SIGUSR1
```

### 6.1 Automatic recovery from persistent display corruption

The display chain of this class of device (DSI panel + touch controller) is
occasionally not fully initialized after DPMS off/restore, showing as touch
firmware load failure or display corruption until the screen is fully toggled
once more.

The daemon handles it like this:

1. After each screen-on, keep the backlight at `0` and first wait for the
   display chain to stabilize;
2. The first screen-on after system suspend wake replaces the normal unblank
   with a full `blank → unblank` recovery cycle (backlight still `0`), even if
   the kernel did not report an error;
3. At the same time, check kernel logs within the screen-on window (use the
   "final failure" record and ignore firmware retries);
4. If an initialization failure is detected, run up to 2 more
   `blank → unblank` recovery cycles; success on any cycle restores brightness;
   only if all fail is brightness restored and a log entry recorded.

## 7. Known issues and notes

1. **Without a graphical session** (e.g. GDM login screen): the compositor
   D-Bus interface is unavailable; it degrades to turning off only the
   backlight (ghost images may remain).
2. **Hardware long power-key press**: PMIC-level force power-off/reset is
   hardware behavior and cannot be disabled in software.
3. **Touch mapping issues**: after display output is disabled/restored the
   compositor may keep the old touch mapping; auto re-adding input devices on
   screen-on mitigates this, but if it is still wrong, try restarting the
   graphical session.
4. **Automatic suspend**: system auto-suspend is not disabled; after wake the
   hook restores the backlight.
5. **GNOME idle-blank interaction**: GNOME idle auto-blank also uses
   `PowerSaveMode=1`; the daemon detects it with background polling and
   refreshes input devices after external input wakes the screen.
6. **Panel stability**: display/touch drivers have instability; every
   screen toggle triggers touch-controller suspend/resume and firmware reload.
   Avoid rapid repeated on/off toggling.
7. **Recovery detection limits**: if a corrupted screen produces no kernel
   error log, the daemon cannot detect it; a manual screen toggle is still
   needed.
8. **Magnetic keyboard**: it may be powered off by hardware during suspend and
   must be physically re-attached after wake.

## 8. Verification

Service status:

```bash
systemctl status screen-toggle.service
systemctl is-enabled screen-toggle.service screen-toggle-resume.service
journalctl -u screen-toggle.service -n 50
```

Screen state (replace paths with your actual devices):

```bash
cat /sys/class/drm/card0-DSI-1/dpms
cat /sys/class/backlight/ktz8866-backlight/brightness
```

Confirm GNOME settings:

```bash
gsettings get org.gnome.settings-daemon.plugins.power power-button-action
gsettings get org.gnome.settings-daemon.plugins.power lid-close-ac-action
gsettings get org.gnome.settings-daemon.plugins.power lid-close-battery-action
```

Simulate power-key/lid events (replace device nodes with the actual ones
auto-detected in `journalctl -u screen-toggle.service` logs):

```bash
python3 - <<'PY'
import os, struct, time
fmt = struct.Struct("<qqHHi")
def ev(t, c, v): return fmt.pack(0, 0, t, c, v)
def inject(path, events):
    fd = os.open(path, os.O_WRONLY)
    try:
        for e in events:
            os.write(fd, e); os.write(fd, ev(0, 0, 0)); time.sleep(0.05)
    finally:
        os.close(fd)
inject("/dev/input/event0", [ev(1, 116, 1), ev(1, 116, 0)])   # power key (example)
inject("/dev/input/event2", [ev(5, 0, 1)])                     # lid close (example)
inject("/dev/input/event2", [ev(5, 0, 0)])                     # lid open (example)
PY
```

## 9. Uninstall / rollback

```bash
sudo systemctl disable --now screen-toggle.service screen-toggle-resume.service
sudo rm -f /etc/systemd/system/screen-toggle.service /etc/systemd/system/screen-toggle-resume.service
sudo rm -f /etc/systemd/logind.conf.d/10-screen-toggle.conf
sudo rm -f /usr/local/sbin/screen-toggle-daemon
sudo rm -rf /var/lib/screen-toggle
sudo systemctl daemon-reload
sudo systemctl restart systemd-logind

# restore GNOME default power actions
gsettings reset org.gnome.settings-daemon.plugins.power power-button-action
gsettings reset org.gnome.settings-daemon.plugins.power lid-close-ac-action
gsettings reset org.gnome.settings-daemon.plugins.power lid-close-battery-action
```

After rollback, the power key returns to the default power-off behavior and
the lid switch returns to the default suspend behavior.
